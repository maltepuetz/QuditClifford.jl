QuditClifford.DoublePauli — Type
DoublePauli(qudit1::Int, x1::Int, z1::Int, qudit2::Int, x2::Int, z2::Int)
DoublePauli(qudit1::Int, x1::Int, z1::Int, qudit2::Int, x2::Int, z2::Int, phase::Int)

Pauli operator acting on two qudits.

Arguments

  • qudit1::Int, qudit2::Int: 1-based qudit indices.
  • x1::Int, z1::Int: Exponents for the first qudit.
  • x2::Int, z2::Int: Exponents for the second qudit.
  • phase::Int: Phase exponent k (interpreted as ω^k or i^k depending on d).

Examples

op = DoublePauli(1, 1, 0, 2, 0, 1)    # X1 * Z2
op = DoublePauli(1, 0, 1, 2, 0, 1, 3) # i^3 Z1 * Z2 when d=2

SinglePauli(qudit::Int, x::Int, z::Int, phase::Int)

Pauli operator acting on a single qudit, with X/Z exponents and an optional phase.

Arguments

  • qudit::Int: 1-based qudit index.
  • x::Int: Exponent of X on that qudit (reduced mod d by consuming functions).

QuditClifford.StabilizerTableau — Type
StabilizerTableau(d::Int, n::Int; state::Symbol=:mixed, basis=:Z, storephase::Bool=true)
StabilizerTableau(d::Int, n::Int, state::Symbol; kwargs...)
StabilizerTableau(d::Int, tableau::AbstractMatrix{<:Integer}; m::Union{Int,Nothing}=nothing, storephase::Union{Bool,Nothing}=nothing)

Construct a stabilizer tableau for an n-qudit stabilizer density operator (mixed-state stabilizer formalism).

Arguments

  • d::Int: Qudit dimension (must be a prime number).
  • n::Int: Number of qudits (only for the d, n constructor).
  • state::Symbol: Preset state for the positional state constructor.
  • tableau::AbstractMatrix{<:Integer}: An integer matrix in either (2n + storephase) × m or m × (2n + storephase) layout.

Keyword Arguments

  • state::Symbol=:mixed: Preset state (:mixed, :product, :ghz). Aliases :X/:Y/:Z map to :product in that basis.
  • basis=:Z: Basis for product states (:X, :Y, :Z, or a per-qudit vector/tuple of Symbols).
  • storephase::Bool=true: Whether to store the phase row (for the (d, n) constructor). When constructing from a tableau, storephase is inferred from the matrix shape if not provided.
  • m::Union{Int,Nothing}=nothing: Number of active generator columns (for the (d, tableau) constructor).
  • inversemod::InverseMod=PrecomputedInvMod(d): Inversion strategy used for phase calculations.

Examples

stab = StabilizerTableau(2, 3; state=:mixed)
stab = StabilizerTableau(2, 3; state=:product, basis=:X)

tab = reshape(Int[0, 1, 0], 3, 1)
stab = StabilizerTableau(2, tab)

Notes

Representation

We store an abelian stabilizer subgroup S generated by m independent commuting Paulis (0 ≤ m ≤ n).

The internal tableau has shape (2n + storephase) × n.

  • Only the first m columns are active generator columns.
  • Columns m+1:n are unused (kept zero) and can be used as capacity when measurements increase m.

Phase convention

If storephase=true, the last row stores the phase exponent k:

  • odd prime d: ω^k with k mod d
  • d=2: i^k with k mod 4

Preset states

  • :mixed (maximally mixed; m=0)
  • :product (pure product state; basis is :X, :Y, :Z, or a vector/tuple of length n)
  • :ghz (generalized GHZ on n qudits)

See also reset!.

QuditClifford.canonicalize! — Method
canonicalize!(stabtab::StabilizerTableau)

Put the active generator columns of stabtab into column-reduced echelon form (RCEF), updating phases consistently and caching pivot metadata.

Arguments

  • stabtab::StabilizerTableau: Tableau to canonicalize in-place.

Returns

  • nothing. Mutates stabtab.

Examples

stab = StabilizerTableau(2, 3; state=:ghz)
canonicalize!(stab)

Notes

  • Operates on columns 1:m (active generators). Columns m+1:n are unused capacity.
  • If storephase=true, the phase row is updated so the represented stabilizer subgroup is unchanged.
  • Updates stabtab.pivcol_of_row, stabtab.xdotz_cache, and sets stabtab.iscanonical = true.

QuditClifford.entanglement_entropy — Method
entanglement_entropy(stabtab::StabilizerTableau, subsystem::AbstractVector)

Compute the stabilizer entanglement entropy of a subsystem.

Arguments

  • stabtab::StabilizerTableau: Stabilizer tableau describing the (possibly mixed) state.
  • subsystem::AbstractVector{<:Integer}: 1-based qudit indices defining subsystem A.

Returns

  • An integer S(A) in log-d units (so S=1 means entropy log(d)).

Examples

stab = StabilizerTableau(2, 3; state=:ghz)
S1 = entanglement_entropy(stab, [1])      # 1
S2 = entanglement_entropy(stab, [1, 2])   # 1

Notes

  • For pure stabilizer states (m == n), the function uses S(A) = S(B) and computes the rank on the smaller side.
  • For mixed stabilizer states (m < n), the function traces out the complement and uses the mixed-state stabilizer formula.
  • subsystem should contain distinct indices; repeated indices lead to undefined results.

Return the expectation value ⟨P⟩ as a ComplexF64 for a Pauli operator op.

Arguments

  • stabtab::StabilizerTableau: Stabilizer tableau (canonicalized if needed).
  • op: Pauli operator as SinglePauli, DoublePauli, TriplePauli, NPauli, or an AbstractVector{<:Integer} of length 2n or 2n+1.

Notes

Delegates to expect_int! and converts the exponent to a complex phase.

QuditClifford.expect_int! — Method
expect_int!(stabtab::StabilizerTableau, op)

Compute the expectation value ⟨P⟩ for a Pauli operator op in exponent form.

Arguments

  • stabtab::StabilizerTableau: Stabilizer tableau (canonicalized if needed).
  • op: Pauli operator as SinglePauli, DoublePauli, TriplePauli, NPauli, or an AbstractVector{<:Integer} of length 2n or 2n+1.

Returns

  • -1 if ⟨P⟩ = 0 (operator not in the stabilizer span).
  • For odd prime d, returns k with ⟨P⟩ = ω^k (k mod d).
  • For d=2, returns k with ⟨P⟩ = i^k (k mod 4).
  • If storephase=false and op is in-span, returns 0 by convention.

Examples

stab = StabilizerTableau(2, 2; state=:product, basis=:Z)
k = expect_int!(stab, SinglePauli(1, 0, 1))  # Z on qudit 1 -> 0 (⟨Z⟩ = 1)
k2 = expect_int!(stab, SinglePauli(1, 1, 0)) # X on qudit 1 -> -1 (⟨X⟩ = 0)

Notes

  • Canonicalizes stabtab if needed, which may permute generator columns and sets iscanonical=true.
  • Uses the preallocated workspaces in stabtab to remain allocation-free.

QuditClifford.measure! — Method
measure!(stabtab::StabilizerTableau, op;
    outcome::Int=rand(0:stabtab.d-1)
)

Projectively measure a Pauli operator op and update stabtab in-place.

Arguments

  • stabtab::StabilizerTableau: Tableau to update.
  • op: Pauli operator specified as SinglePauli, DoublePauli, TriplePauli, NPauli, or an AbstractVector{<:Integer} of length 2n or 2n+1.

Keyword Arguments

  • outcome::Int=rand(0:stabtab.d-1): Outcome used when the measurement is non-deterministic (uniform on 0:(d-1)).

Returns

  • Integer outcome t.
  • For odd prime d, the measured eigenvalue is ω^t (mod d).
  • For d=2, the eigenvalue exponent is returned in deterministic cases when storephase=true (values 0:3 for i^t). In non-deterministic branches, the returned value is exactly outcome.

Examples

stab = StabilizerTableau(2, 2; state=:product, basis=:Z)
op = SinglePauli(1, 1, 0)           # X on qudit 1
t = measure!(stab, op)              # random outcome, tableau updated

stab3 = StabilizerTableau(3, 2; state=:ghz)
op3 = DoublePauli(1, 0, 1, 2, 0, 2) # Z1 * Z2^2
t3 = measure!(stab3, op3)           # deterministic outcome t3=0, tableau unchanged

Notes

  • If op does not commute with all generators, the outcome is random and the first non-commuting generator is replaced; other non-commuting generators are adjusted to restore commutation.
  • If op commutes with all generators, the outcome is deterministic when op lies in the stabilizer span; otherwise a new generator is appended (if m < n).
  • If storephase=false, deterministic outcomes return 0 by convention.

QuditClifford.mul_col_by_workspace_power! — Method

Multiply a tableau column by (generator_workspace)^a on the RIGHT, with correct phase updates.

This is used in the noncommuting measurement update: gi <- gi * (gpivot)^a where gpivot is stored in generator_workspace.

  • XZ rows are updated linearly mod d.
  • If storephase=false: no phase bookkeeping.
  • If storephase=true: odd prime d: (ω^k X^x Z^z)(ω^k' X^x' Z^z') = ω^(k+k' + x'·z) X^(x+x') Z^(z+z') d=2: use phase mod 4 as i^k and cross-term contributes 2*(x'·z) mod 4.
