Conventions ​

Tableau layout ​

A tableau stores generators in columns. For n qudits, tab.stab has rows 1:n for the X exponents, rows n+1:2n for the Z exponents, and, when storephase=true, row 2n + 1 for the phase exponents. The first m columns are the active generators, with   . The remaining columns are zeroed capacity for measurements that raise m. A pure state has m = n; a mixed state has m < n. Tableaux covers construction from a raw matrix.

Computational basis ​

state_vector and density_matrix index the computational basis with qudit 1 as the most significant digit:

so the vector of a product state is kron of its factors in qudit order, and a label prints in reading order. This is independent of the tableau layout, which groups every X row before every Z row. ket fixes the global phase by making the amplitude of the lexicographically first label real and positive, and state_vector keeps that choice.

A measure! outcome uses the same encoding in every branch and for the outcome keyword, so a repeated measurement returns the outcome of the first. For qubits it counts in units of , while expect_int! counts in units of , so eigenvalue is 1 for the first and 2 for the second:

julia
julia> tab = DestabilizerTableau(2, 1; state = :product, basis = :Z);

julia> measure!(tab, SinglePauli(1, 1, 0); outcome = 1), measure!(tab, SinglePauli(1, 1, 0))
(1, 1)

julia> expect_int!(tab, SinglePauli(1, 1, 0))
2

With storephase=false, a deterministic measurement returns 0 and expect_int! returns 0 for an operator in the stabilizer group, because the phase was not stored. Measurements, Expectations and Channels shows all three functions in use.
